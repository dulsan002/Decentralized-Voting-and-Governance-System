# 12 — Web3 Integration

## Technology

- **Library:** ethers.js v6
- **Wallet:** MetaMask (browser extension)
- **Networks:** Hardhat local (development), Sepolia (testnet)

## Connection Architecture

```
Browser
  ↓
window.ethereum (MetaMask Provider)
  ↓
ethers.BrowserProvider (wraps MetaMask)
  ↓
Signer (for write operations)
Provider (for read operations)
  ↓
Contract Instance (ABI + Address)
  ↓
Blockchain
```

## Wallet Connection Flow

1. Check `window.ethereum` exists
2. Call `eth_requestAccounts` to prompt MetaMask
3. Create `BrowserProvider` from `window.ethereum`
4. Get `Signer` for transaction signing
5. Get connected chain ID for network validation
6. Store wallet state in `WalletProvider` context

## Contract Interaction Pattern

### Read Operations (No Gas)
```typescript
const contract = new ethers.Contract(address, abi, provider);
const election = await contract.getElection(electionId);
```

### Write Operations (Requires Gas + Signature)
```typescript
const contract = new ethers.Contract(address, abi, signer);
const tx = await contract.castBallot(electionId, pref1, pref2);
const receipt = await tx.wait(); // Wait for confirmation
```

## Transaction Lifecycle (UI States)

```
IDLE
  ↓ User clicks "Submit"
PREPARING
  ↓ Frontend calls contract method
AWAITING_SIGNATURE
  ↓ MetaMask popup appears
  ├─→ User rejects → REJECTED (show error)
  ↓ User signs
PENDING
  ↓ Transaction submitted to network
  ↓ Show tx hash, spinner
CONFIRMING
  ↓ tx.wait() resolves
  ├─→ Receipt status 0 → FAILED (show revert reason)
  ↓ Receipt status 1
CONFIRMED
  ↓ Update UI with confirmation
```

## Error Handling

| Error | Detection | User Message |
|-------|-----------|-------------|
| MetaMask not installed | `!window.ethereum` | "Please install MetaMask" |
| User rejected connection | Error code 4001 | "Connection request was rejected" |
| User rejected transaction | Error code 4001 | "Transaction was rejected" |
| Wrong network | Chain ID mismatch | "Please switch to [Network]" |
| Account changed | `accountsChanged` event | "Account changed — reconnecting" |
| Chain changed | `chainChanged` event | "Network changed — please verify" |
| Insufficient gas | Estimategas failure | "Insufficient ETH for transaction" |
| Contract revert | Custom error parsing | Display parsed revert reason |
| Transaction pending timeout | Long wait | "Transaction still pending" |
| RPC error | Provider error | "Network error — please retry" |

## ABI Management

The compiled contract ABI is generated by Hardhat and copied to the frontend:

```
contracts/ → Hardhat compile → artifacts/ → copy ABI → lib/contracts/DecentraVote.json
```

A deployment script or post-compile hook will automate this.
